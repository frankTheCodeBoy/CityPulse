## 📋 Next Steps (5 Easy Phases)

### Phase 1: Setup Neon PostgreSQL (5 min)
1. Go to https://console.neon.tech/
2. Sign up (free, no credit card)
3. Create database "citypulse"
4. Copy PostgreSQL connection string
5. **Keep it safe** — you'll need this

### Phase 2: Deploy Backend to Render (20 min)
1. Go to https://render.com
2. Sign up (connect GitHub)
3. Create new Web Service
4. Select your GitHub repo
5. Set `DATABASE_URL` env variable (from Neon)
6. Set `ENVIRONMENT=production`
7. Deploy
8. Seed database: `python -m backend.seed`
9. **Copy your Render URL**

### Phase 3: Deploy Frontend to Vercel (15 min)
1. Go to https://vercel.com
2. Sign up (connect GitHub)
3. Import your repo
4. Set `REACT_APP_API_URL` = your Render URL
5. Deploy
6. **You get your Vercel URL**

## 🎯 Interview Talking Points

### "Tell me about your deployment"
> "I'm deploying CityPulse across three free platforms: Vercel hosts the React frontend with automatic deployments on git push, Render hosts the FastAPI backend in a Docker container, and Neon provides the PostgreSQL database. The backend uses environment variables for secrets and NullPool connection pooling recommended for serverless databases. I've configured CORS to only allow requests from the frontend domain, and implemented health checks for monitoring. It's a production-ready architecture that demonstrates understanding of containerization, database optimization, and modern deployment practices."

### "Why these platforms?"
> "These platforms were chosen for their free tiers that don't require credit cards, making it ideal for a portfolio project. Vercel provides fast global CDN deployment with automatic HTTPS, Render offers containerization support, and Neon provides reliable PostgreSQL without sleep timers. The architecture is cost-effective while maintaining production quality."

### "How do you handle secrets?"
> "All secrets are stored as environment variables in each platform's dashboard—never committed to Git. The backend reads DATABASE_URL and ENVIRONMENT from env vars, and the frontend reads API_URL. I use .env.example as a template that documents required variables without exposing actual credentials."
